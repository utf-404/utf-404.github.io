01

프로젝트 개요

문제

계량기는 고정 길이 바이트 프레임, PLC는 순간 상태값, AMR는 UDP JSON을 사용했습니다. 형식과 갱신 시점이 달라 원시 데이터를 그대로 기록하면 잘못된 무게나 중복 작업이 운영 이력에 남을 수 있었습니다.

접근

각 장비 경계에서 프레임과 스키마를 먼저 검증하고, 상승 에지와 작업 식별자를 기준으로 의미 있는 이벤트만 생성했습니다. 하드웨어가 없을 때도 송신기와 sample 모드로 인터페이스를 확인할 수 있게 분리했습니다.

02

담당 범위

장비 통신

  • CI-600A Command Type 1 명령 및 22바이트 응답 파서
  • 멀티포트 USB-RS232 수신과 상태·램프·릴레이 비트 해석
  • PLC snapshot을 IF_RN_102 중량 메시지로 변환

로봇·운영 연동

  • IF_RN_103/104 UDP JSON 검증과 ROS2 노드 구성
  • 작업 문맥에 따른 PLC 서비스 선택과 응답 처리
  • 컨베이어, 조합, 카메라 상태와 이벤트 이력 UI 구현

04

핵심 구현

고정 길이 프레임 파싱

22바이트 길이, 쉼표 위치, CRLF, ST·US·OL 상태와 GS·NT 형식을 확인한 뒤 무게를 숫자로 변환합니다. 음수 값 내부의 공백도 정규화하고 잘못된 프레임은 운영 값으로 사용하지 않습니다.

작업 이벤트 생성

트레이가 empty에서 full로 바뀌는 상승 에지를 감지하고 0.5초 뒤 유효한 무게를 읽습니다. 조합 중량과 선택 트레이 서명을 비교해 같은 결과의 중복 기록을 억제합니다.

AMR 작업 문맥 연결

원물통 교체 요청의 task ID, 원물과 위치 정보를 보관한 뒤 펜스 진입·진출 메시지에 맞는 PLC 서비스를 선택합니다. 알 수 없는 ID와 잘못된 enum 값은 경계에서 거부합니다.

운영 상태 가시화

대기·계량·메모리 컨베이어, 조합 선택과 return 상태를 부분 갱신하고 카메라 압축 이미지와 처리 상태를 함께 제공합니다. 이벤트 변경분만 CSV에 남겨 원시 polling 값과 작업 이력을 구분합니다.

05

문제 해결

시리얼 응답이 나뉘어 도착

한 번의 read가 한 프레임이라는 가정을 제거했습니다. 수신 바이트를 누적하고 CRLF 단위로 완성된 프레임만 꺼내며, 남은 조각은 다음 수신까지 보존했습니다.

센서 상태와 이벤트 시점 불일치

PLC 비트가 올라오는 순간의 무게는 아직 안정되지 않을 수 있었습니다. 상승 에지를 기준으로 지연 샘플링하고 첫 snapshot은 기준값으로만 사용해 시작 시 거짓 이벤트를 막았습니다.

같은 작업의 중복 기록

주기적으로 같은 조합 결과가 전달되는 경우 중량과 선택 트레이로 signature를 만들고 이전 값과 같으면 저장하지 않도록 했습니다.

하드웨어 의존 테스트

PLC 연결 없이 JSON 생성과 HTTP 수신을 확인하는 sample 모드, AMR 요청·응답을 재현하는 UDP sender를 분리해 인터페이스 문제를 장비 문제와 구분했습니다.

06

검증 결과와 한계

장비의 원시 값을 운영 이벤트로 바꾸는 경계를 코드로 명확히 했습니다.

고정 길이 프레임 검증, 상태 상승 에지, 지연 샘플링, 중복 signature와 독립 송신 테스트를 통해 통신 오류와 작업 로직 오류를 분리해 확인할 수 있습니다. 다만 저장소에는 장시간 운전 지표와 자동화 회귀 테스트가 없어, 안정성을 수치로 주장하지 않고 현재 한계로 남겼습니다.
