로봇 제어 및 모니터링 웹 시스템

로봇, PLC, 작업 데이터와 운영 화면을 하나의 흐름으로 연결해 현장 상태를 실시간으로 확인할 수 있도록 구성했습니다.

Role
Web–Robot System Integration
Interface

Backend

Device
ROS2 Robot · PLC
개요담당 범위아키텍처핵심 구현문제 해결결과
01

프로젝트 개요

목표

분리되어 있는 작업 정보, 로봇 상태와 PLC 연결 상태를 운영자가 웹에서 빠르게 파악하고 제어 흐름까지 확인할 수 있는 시스템을 구성하는 것이 목표였습니다.

접근 방식

FastAPI를 중심으로 ROS2와 설비 데이터를 연결하고, PostgreSQL에는 작업 및 상태 이력을 저장하며, 변경되는 상태는 WebSocket으로 운영 화면에 전달하도록 구성했습니다.

02

담당 범위

연동 구조 설계

  • ROS2 로봇 상태와 웹 서버 사이의 데이터 흐름 구성
  • PLC 연결·동작 상태를 운영 화면에서 표현할 구조 검토
  • API, WebSocket과 DB 저장 역할 분리

운영 UI 구현

  • 작업 지시와 진행 현황 표시
  • 로봇·PLC 연결 상태 및 경고 표현
  • 현장 작업 흐름을 기준으로 정보 우선순위 구성
03

시스템 아키텍처

  1. Operator UI작업 지시 · 상태 확인
  2. FastAPIREST API · WebSocket
  3. Integration Layer상태 변환 · 명령 전달
  4. ROS2 / PLC로봇 · 설비 인터페이스
  5. PostgreSQL작업 · 상태 이력

초안 흐름도입니다. 실제 토픽명, PLC 통신 방식, DB 테이블 관계를 추가하면 구현 근거가 더 명확해집니다.

04

핵심 구현

실시간 상태 반영

주기적으로 새로고침하지 않아도 로봇과 PLC 상태 변화가 운영 화면에 반영되도록 WebSocket 기반 전달 흐름을 구성했습니다.

API와 이력 데이터

작업 지시와 조회 기능은 API로 분리하고, 작업 현황과 상태 이력을 PostgreSQL에서 관리할 수 있는 저장 구조를 설계했습니다.

설비 상태 시각화

연결 여부, 현재 작업, 경고와 로봇 상태를 운영자가 한 화면에서 구분할 수 있도록 대시보드 정보 구조를 구성했습니다.

현장 중심 흐름

기술 컴포넌트의 구분보다 실제 작업 순서와 운영자가 확인해야 할 정보를 기준으로 화면을 설계했습니다.

05

문제 해결 관점

서로 다른 상태 체계

로봇, PLC와 웹 UI가 사용하는 상태 표현을 운영 화면에서 일관되게 이해할 수 있도록 연결 계층에서 변환하는 구조가 필요했습니다.

실시간 정보와 이력의 분리

즉시 전달해야 하는 상태와 장기 보관할 작업 이력을 구분해 WebSocket과 PostgreSQL의 책임을 나누었습니다.

06

결과와 다음 검증

로봇과 설비의 상태를 웹 운영 흐름으로 연결했습니다.

현재 초안에는 구현 범위 중심으로 정리했습니다. 실제 포트폴리오에는 상태 반영 지연, 장시간 연결 안정성, 데이터 누락 여부, 운영 테스트 횟수와 본인 기여도를 추가하는 것이 좋습니다.
