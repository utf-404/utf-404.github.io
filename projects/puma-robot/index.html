01

프로젝트 개요

목표

웹에서 입력한 세 관절의 목표값을 ROS2 메시지로 전달하고, 같은 명령 상태를 RViz와 웹에서 확인하는 최소 통합 구조를 구성했습니다.

범위

이 프로젝트는 실제 모터나 ros2_control을 구동하는 폐루프 제어기가 아닙니다. 명령 검증, 토픽 연결, URDF 상태 반영과 웹 브리지의 인터페이스를 검증하는 데모입니다.

02

담당 범위

로봇 모델

  • 3-DOF 링크·관절 URDF/Xacro 구성
  • mesh 경로, joint limit와 TF 계층 설정
  • robot_state_publisher 및 RViz 설정

ROS2·웹 연결

  • 관절 명령과 명령 상태 토픽 구성
  • FastAPI 정적 UI와 두 WebSocket 경로 구현
  • 공통 입력 검증 함수와 pytest 테스트 작성

제어 노드와 웹 브리지가 같은 검증 함수를 사용해 웹과 ROS2 어느 경로에서 들어와도 동일한 관절 제한을 적용합니다.

04

핵심 구현

공통 명령 검증

세 개의 유한한 숫자인지 확인하고 관절별 허용 범위를 벗어난 값은 제한값으로 보정합니다. 개수 부족, NaN과 문자열 입력은 ROS 메시지로 발행하지 않습니다.

명령·로그 소켓 분리

/ws는 관절 명령을 받고 /ws_log는 상태와 로그를 전달합니다. UI 입력 경로와 관찰 경로를 분리해 메시지 역할을 명확히 했습니다.

통합 실행

launch 파일 하나로 robot_state_publisher, 정적 TF, 제어 노드, 웹 브리지와 RViz를 실행합니다. 각 노드를 수동으로 시작할 때 생기는 설정 차이를 줄였습니다.

테스트 가능한 순수 로직

ROS2 런타임과 무관한 입력 검증을 별도 함수로 분리했습니다. 정상값, 제한값 보정과 세 종류의 잘못된 입력을 포함한 5개 테스트 케이스를 저장소에 포함했습니다.

05

문제 해결

검증 로직 불일치

웹과 ROS 노드에서 관절 제한을 따로 처리하면 결과가 달라질 수 있습니다. 공통 모듈로 이동해 두 경로가 같은 규칙과 오류 메시지를 사용하도록 했습니다.

프레임·자산 경로

RViz에서 모델이 누락되거나 위치가 어긋나는 문제를 package share 경로와 world–base_link 정적 TF를 기준으로 정리했습니다.

06

검증 결과와 한계

Robot model–ROS2 topic–WebSocket 경계를 작게 연결하고 입력 계약을 테스트했습니다.

저장소에서 정상 명령, joint limit 보정과 잘못된 입력 거부를 5개 테스트 케이스로 확인할 수 있습니다. 화면의 현재값은 실제 엔코더 피드백이 아니라 제어 노드가 승인한 명령을 JointState로 반영한 값이며, 실제 하드웨어 제어 경험으로 표현하지 않습니다.
