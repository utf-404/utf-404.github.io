01

프로젝트 개요

목표

ROS2에서 로봇 모델을 시각화하는 단계에 그치지 않고, 웹에서 입력한 관절 명령이 제어 노드와 RViz 상태까지 이어지는 전체 흐름을 구성했습니다.

실행 구조

하나의 launch 파일로 robot_state_publisher, 관절 컨트롤러, 웹 브리지, 정적 TF와 RViz2가 함께 실행되도록 패키지를 구성했습니다.

02

담당 범위

로봇 모델

  • 3-DOF PUMA 타입 링크와 관절 구조 작성
  • URDF/Xacro 분리 및 mesh·frame 경로 구성
  • 관절 범위와 world–base_link TF 설정

제어와 웹 연동

  • 관절 명령 및 상태 토픽 연결
  • 웹 명령과 상태 로그용 WebSocket 구성
  • 수동·랜덤 모션 및 현재 관절값 UI 구현
03

시스템 아키텍처

  1. Web UI관절 목표값 · 모션 제어
  2. Web BridgeHTTP · WebSocket
  3. ROS2 Topics/joint_commands · /joint_states
  4. PUMA Controller범위 검증 · 상태 발행
  5. RViz2Robot State 시각화

명령은 `/joint_commands`, 현재 상태는 `/joint_states`를 사용하며, 웹 상태와 로그는 별도 WebSocket 경로로 전달합니다.

04

핵심 구현

관절 명령 검증

세 관절의 목표값 개수와 형식을 검사하고, 허용 범위를 벗어난 값은 관절 제한값 안으로 보정하도록 구성했습니다.

실시간 상태 표시

ROS2에서 발행되는 현재 관절값을 웹 UI와 RViz에 반영해 명령과 실제 상태 흐름을 함께 확인할 수 있습니다.

통합 실행

필요한 노드와 웹 서버를 개별 실행하지 않아도 launch 파일 하나로 전체 시스템을 시작할 수 있도록 구성했습니다.

동작 모드

슬라이더 수동 제어, 제한 범위 내 랜덤 명령, 반복 모션 시작·정지 기능으로 제어 흐름을 점검할 수 있습니다.

05

문제 해결 관점

모델 경로와 프레임

URDF/Xacro의 mesh 경로와 frame 연결이 어긋나면 RViz에서 모델이 누락되거나 잘못 배치되므로 ROS2 package path와 TF 계층을 함께 점검했습니다.

웹 입력의 안전한 전달

웹에서 잘못된 개수나 형식의 명령이 들어오는 경우를 거부하고, 관절 제한을 적용해 제어 노드가 유효한 값만 처리하도록 구성했습니다.

06

결과와 다음 검증

Robot model–ROS2 control–Web UI를 하나의 실행 흐름으로 완성했습니다.

저장소에는 요구사항, 실행 방법, ROS 인터페이스와 테스트 명령이 정리되어 있습니다. 다음 단계에서는 자동 테스트 범위와 명령·상태 지연 측정 결과를 상세히 추가할 수 있습니다.
